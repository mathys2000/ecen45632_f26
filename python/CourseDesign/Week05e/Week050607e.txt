### **Lecture 9: Time/Frequency Responses and Group Delay**

**Primary Readings:** O&S Chapter 5 (Sections 5.1–5.4)
**Focus:** Analyzing LTI systems via pole-zero plots and understanding the physical significance of phase and group delay in signal representation.

**0:00 – 0:10 | Introduction & Motivation: Why Phase Matters**

* **The ML Context:** In time-series classification (e.g., ECG anomaly detection) or audio processing, passing raw data through a filter (or a 1D CNN) modifies the signal. Magnitude changes frequency content; phase changes the *shape* of the waveform in the time domain.
* **Core Concept:** Review the frequency response $H(e^{j\omega}) = \vert{}H(e^{j\omega})\vert{}e^{j\angle H(e^{j\omega})}$.

**0:10 – 0:30 | Frequency Response from Poles and Zeros**

* **Rational System Functions:** Expressing $H(z)$ as a ratio of polynomials.
* **Geometric Evaluation:** How to visualize magnitude $\vert{}H(e^{j\omega})\vert{}$ and phase $\angle H(e^{j\omega})$ directly from the pole-zero plot on the z-plane.
* **Vector Analysis:** Using vector lengths from zeros (numerator) and poles (denominator) to the unit circle to sketch filter responses (lowpass, highpass, bandpass).

**0:30 – 0:55 | Phase Distortion and Group Delay**

* **Phase Delay vs. Group Delay:**
* Phase Delay: $\tau_p(\omega) = -\frac{\angle H(e^{j\omega})}{\omega}$ (delay of the carrier).
* Group Delay: $\tau_g(\omega) = -\frac{d}{d\omega} \angle H(e^{j\omega})$ (delay of the signal envelope/information).


* **Non-linear Phase:** Demonstrate how a filter with non-linear phase (and thus, frequency-dependent group delay) causes different frequency components of a signal to be delayed by different amounts, leading to "dispersion" or severe distortion of the time-domain waveform.

**0:55 – 1:10 | All-Pass Systems (The Phase Modifier)**

* **Definition:** Systems where $\vert{}H(e^{j\omega})\vert{} = 1$ for all $\omega$, but phase is modified.
* **Pole-Zero Symmetry:** Poles and zeros exist in conjugate reciprocal pairs (e.g., pole at $z=a$, zero at $z=1/a^*$).
* **Application:** Phase equalization. If an IIR filter introduces phase distortion, an all-pass filter can be cascaded to flatten the overall group delay.

### **Lecture 10: Linear Phase, Generalized Linear Phase, and ML Intersections**

**Primary Readings:** O&S Chapter 5 (Section 5.7); Conceptual bridge to Raschka (1D Convolutions).
**Focus:** The constraints required for linear phase, the four types of FIR linear phase filters, and how this translates to learned filters in machine learning.

**0:00 – 0:15 | The Concept of Exact Linear Phase**

* **Definition:** A system has exact linear phase if $\angle H(e^{j\omega}) = -\alpha\omega$.
* **Time-Domain Implication:** Constant group delay ($\tau_g = \alpha$). The entire signal is shifted uniformly in time by $\alpha$ samples, preserving the exact shape of the waveform.
* **The FIR Requirement:** Show mathematically why only Finite Impulse Response (FIR) filters can achieve exact linear phase.

**0:15 – 0:40 | Generalized Linear Phase and Symmetry Constraints**

* **Generalized Linear Phase:** $\angle H(e^{j\omega}) = \beta - \alpha\omega$. (Allows for a constant phase offset $\beta$, typically $0$ or $\pi/2$).
* **Symmetry Requirements:** Prove that for an FIR filter to have generalized linear phase, its impulse response $h[n]$ must be either symmetric ($h[n] = h[M-n]$) or anti-symmetric ($h[n] = -h[M-n]$).
* **The Four Types of FIR Filters:**
* Type I: Symmetric, Even length ($M$ is even).
* Type II: Symmetric, Odd length ($M$ is odd).
* Type III: Anti-symmetric, Even length.
* Type IV: Anti-symmetric, Odd length.


* *Note on constraints:* Explain why Type II cannot be a high-pass filter (must have a zero at $\omega = \pi$) and Type III/IV are suited for differentiators or Hilbert transformers.

**0:40 – 0:55 | Zero Locations of Linear Phase Systems**

* **The Root Locus Constraint:** If $z_0$ is a zero, then $1/z_0$ must also be a zero (due to symmetry). If $h[n]$ is real, $z_0^*$ and $1/z_0^*$ must also be zeros.
* **Visualizing the Z-Plane:** Show the classic 4-zero constellation (radius $r$, $1/r$, angles $\pm \theta$) and zeros constrained to the unit circle or real axis.

**0:55 – 1:10 | DSP to ML Bridge: Convolutions as Filters**

* **1D Convolutions in PyTorch:** Frame a `nn.Conv1d` layer as a trainable FIR filter.
* **Do Neural Networks Learn Linear Phase?** By default, no. The weights are initialized randomly (without symmetry constraints).
* **Inductive Bias:** Discuss scenarios in time-series forecasting or biosignal processing where you might want to enforce symmetric weights in a custom PyTorch convolutional layer to preserve waveform shape, versus letting the network learn phase distortion if it helps maximize the objective function (e.g., cross-entropy loss).

Here is the complete Python code for **Part 1: FIR Filter Design and Baseline Frequency Analysis**.

This script uses `numpy` and `scipy.signal` to generate a baseline signal (a clean low-frequency signal mixed with high-frequency noise), analyze its frequency spectrum using the Fast Fourier Transform (FFT), and design a Lowpass FIR filter to clean it up.

### Python Implementation

```python
import numpy as np
import matplotlib.pyplot as plt
from scipy import signal
from scipy.fft import fft, fftfreq

# ==========================================
# 1. Generate the Baseline Signal
# ==========================================
fs = 1000.0       # Sampling frequency (Hz)
t_max = 1.0       # Duration (seconds)
t = np.arange(0, t_max, 1/fs)

# Create a signal: 10 Hz (desired) + 150 Hz (interference/noise)
freq_desired = 10.0
freq_noise = 150.0
x = np.sin(2 * np.pi * freq_desired * t) + 0.5 * np.sin(2 * np.pi * freq_noise * t)

# Add a little bit of random white noise for realism
np.random.seed(42)
x += 0.2 * np.random.randn(len(t))

# ==========================================
# 2. Baseline Frequency Analysis (FFT)
# ==========================================
N = len(x)
yf = fft(x)
xf = fftfreq(N, 1/fs)[:N//2]
# Calculate magnitude (normalized)
mag_yf = 2.0/N * np.abs(yf[0:N//2])

# ==========================================
# 3. FIR Filter Design
# ==========================================
# Design a Lowpass FIR filter to keep the 10 Hz signal and remove the 150 Hz noise
num_taps = 101        # Filter order (number of taps)
cutoff_hz = 50.0      # Cutoff frequency in Hz

# Use the window method (Hamming window by default)
fir_coeff = signal.firwin(num_taps, cutoff_hz, fs=fs)

# Calculate the frequency response of the filter
w, h = signal.freqz(fir_coeff, worN=8000, fs=fs)

# ==========================================
# 4. Plotting the Results
# ==========================================
fig = plt.figure(figsize=(14, 10))

# Plot A: Time-domain baseline signal
ax1 = plt.subplot(3, 1, 1)
ax1.plot(t, x, label='Original Signal', color='lightcoral')
ax1.set_title('Baseline Signal in Time Domain')
ax1.set_xlabel('Time [s]')
ax1.set_ylabel('Amplitude')
ax1.grid(True)
ax1.legend()

# Plot B: Frequency-domain analysis (Spectrum)
ax2 = plt.subplot(3, 1, 2)
ax2.plot(xf, mag_yf, color='purple', label='Signal Spectrum')
ax2.set_title('Baseline Frequency Analysis (FFT)')
ax2.set_xlabel('Frequency [Hz]')
ax2.set_ylabel('Magnitude')
ax2.grid(True)
ax2.legend()
# Highlight the noise and desired frequencies
ax2.axvline(freq_desired, color='g', linestyle='--', alpha=0.6, label='Desired (10 Hz)')
ax2.axvline(freq_noise, color='r', linestyle='--', alpha=0.6, label='Noise (150 Hz)')
ax2.legend()

# Plot C: FIR Filter Frequency Response
ax3 = plt.subplot(3, 1, 3)
# Convert magnitude to Decibels (dB)
mag_db = 20 * np.log10(np.maximum(np.abs(h), 1e-5)) 
ax3.plot(w, mag_db, 'b', label='FIR Filter Response')
ax3.axvline(cutoff_hz, color='orange', linestyle='--', label=f'Cutoff ({cutoff_hz} Hz)')
ax3.set_title('FIR Filter Frequency Response (Magnitude)')
ax3.set_xlabel('Frequency [Hz]')
ax3.set_ylabel('Magnitude [dB]')
ax3.set_ylim([-100, 10])
ax3.grid(True)
ax3.legend()

plt.tight_layout()
plt.show()

```

### What this code does:

1. **Time Domain Baseline:** Creates a composite signal sampled at $F_s = 1000$ Hz. It combines a low-frequency $10$ Hz sine wave (our "good" signal) with a high-frequency $150$ Hz sine wave and some white noise.
2. **Frequency Analysis:** Uses `scipy.fft` to compute the discrete Fourier transform. The resulting plot clearly identifies the spikes at $10$ Hz and $150$ Hz.
3. **Filter Design:** Uses `scipy.signal.firwin` to design a 101-tap Lowpass FIR filter with a cutoff frequency of $50$ Hz.
4. **Filter Response:** Uses `scipy.signal.freqz` to evaluate the filter's frequency response, plotted in decibels (dB) to show how steeply it attenuates the stopband (everything above $50$ Hz).

### Analyzing the Visual Artifacts

When you run this code, the spectrograms will display a stark contrast in how the frequency content is handled during downsampling:

* **The Anti-Aliased Output:** You will see a single, clean diagonal line that starts at 0 Hz and stops abruptly around 1.25 seconds. Because the cutoff frequency is $\pi/4$ (which corresponds to 2000 Hz in the original 16000 Hz signal), the FIR filter cleanly eliminates the rest of the chirp before the stride operation discards samples.
* **The Aliased Artifacts (The "V" Shapes):** In the randomly initialized baseline, the spectrogram will show a zig-zag or "V-shaped" pattern reflecting back and forth between 0 Hz and 2000 Hz across the entire 5 seconds. For example, the original 3000 Hz tone appears incorrectly as a 1000 Hz tone in the decimated output.

This demonstrates why applying standard strided convolutions to raw data without sufficient spatial or temporal anti-aliasing destroys shift-equivariance in neural networks.

Gemini Flash-Lite:

Here is the implementation of the First Noble Identity in PyTorch.

Because standard PyTorch convolution (`F.conv1d`) computes cross-correlation ($y[n] = \sum x[n+i]w[i]$), we can perfectly map a strided convolution into $M$ parallel unstrided convolutions at the lower sample rate. We achieve this by reshaping both the input tensor and the filter weights into $M=4$ separate channels using zero-copy tensor views.

```python
import torch
import torch.nn.functional as F
import time
import numpy as np
from scipy.signal import chirp, firwin

# ==========================================
# 1. Recreate Setup from Parts 1 & 2
# ==========================================
fs = 16000
duration = 5
M = 4  # Decimation factor

# Generate Chirp (1, 1, 80000)
t = np.linspace(0, duration, duration * fs, endpoint=False)
x_np = chirp(t, f0=0, f1=8000, t1=duration, method='linear')
x = torch.tensor(x_np, dtype=torch.float32).view(1, 1, -1)

# Generate 64-tap FIR filter (1, 1, 64)
fir_coeffs = torch.tensor(
    firwin(64, cutoff=1.0/M, window='hamming'), 
    dtype=torch.float32
).view(1, 1, 64)

# ==========================================
# 2. The Aliased Baseline (Standard Strided Conv)
# ==========================================
# Standard approach: compute everything, stride down
y_baseline = F.conv1d(x, fir_coeffs, stride=M)

# ==========================================
# 3. The Polyphase Decimator
# ==========================================
# Decompose the filter into M=4 branches of 16 taps.
# view(16, 4) groups the coefficients, transpose moves the phase offset to the channel dimension.
# Final shape: (out_channels=4, in_channels/groups=1, kernel_size=16)
w_poly = fir_coeffs.view(16, M).transpose(0, 1).unsqueeze(1).contiguous()

# Decompose the input signal into M=4 phases.
# view(-1, 4) groups temporal samples, transpose makes them parallel channels.
# Final shape: (batch=1, channels=4, length=20000)
x_poly = x.view(1, -1, M).transpose(1, 2)

# Compute polyphase convolution directly at the lower rate
# groups=4 ensures each input channel is convolved ONLY with its corresponding sub-filter
y_poly_channels = F.conv1d(x_poly, w_poly, stride=1, groups=M)

# Sum across the channels to perfectly reconstruct the decimated signal
y_poly = y_poly_channels.sum(dim=1, keepdim=True)

# ==========================================
# 4. Validation and Benchmarking
# ==========================================
# 1. Verify exact numerical equivalence
is_equivalent = torch.allclose(y_baseline, y_poly, atol=1e-6)
print(f"Are the outputs mathematically identical? {is_equivalent}")

# 2. Measure Execution Speedup
iterations = 1000

# Benchmark Baseline
start_time = time.perf_counter()
for _ in range(iterations):
    _ = F.conv1d(x, fir_coeffs, stride=M)
baseline_time = time.perf_counter() - start_time

# Benchmark Polyphase
start_time = time.perf_counter()
for _ in range(iterations):
    x_p = x.view(1, -1, M).transpose(1, 2)
    _ = F.conv1d(x_p, w_poly, stride=1, groups=M).sum(dim=1, keepdim=True)
polyphase_time = time.perf_counter() - start_time

print(f"\nExecution Time over {iterations} passes:")
print(f"Standard Strided Conv: {baseline_time:.4f} seconds")
print(f"Polyphase Decimator:   {polyphase_time:.4f} seconds")
print(f"Speedup Factor:        {baseline_time / polyphase_time:.2f}x")

```

### Making Polyphase Filters Trainable

To modify this polyphase implementation into a trainable ML layer, you simply replace the fixed FIR weights (`w_poly`) with PyTorch's native Depthwise Convolution layer.

Instead of loading predefined filter coefficients, you instantiate a grouped convolution like this:

```python
import torch.nn as nn

# in_channels=4, out_channels=4, groups=4 means each branch gets its own trainable filter
trainable_polyphase_layer = nn.Conv1d(
    in_channels=M, 
    out_channels=M, 
    kernel_size=64//M, 
    groups=M, 
    stride=1, 
    bias=False
)

# Forward pass
x_poly = x.view(1, -1, M).transpose(1, 2)
y_channels = trainable_polyphase_layer(x_poly)
y_final = y_channels.sum(dim=1, keepdim=True)

```

Because all operations (the reshape, the grouped convolution, and the summation) are fully differentiable, you can drop this directly into a PyTorch model. Backpropagation will push gradients through the summation and update the polyphase coefficients to learn the optimal task-specific anti-aliasing filter, natively operating at the lower sample rate.

A two-channel analysis filter bank splits an input signal into a low-frequency subband and a high-frequency subband, followed by downsampling by $M=2$ in each branch. By applying polyphase decomposition, we avoid filtering the high-rate signal directly; instead, we route the split phases through a $2 \times 2$ polyphase matrix operating entirely at the lower sample rate.

### Python Implementation of a Two-Channel Polyphase Analysis Bank

The implementation below uses a prototype lowpass filter and modulates it to create a complementary highpass filter (a classic Quadrature Mirror Filter setup), decomposes both into their even and odd polyphase components, and processes them using PyTorch's native multi-channel convolution.

```python
import torch
import torch.nn.functional as F
import numpy as np
from scipy.signal import firwin
import matplotlib.pyplot as plt

# ==========================================
# 1. Signal and Filter Bank Setup (M = 2)
# ==========================================
fs = 16000
duration = 0.5
t = np.linspace(0, duration, int(fs * duration), endpoint=False)

# Create a test signal containing a low tone (500 Hz) and a high tone (4000 Hz)
x_np = np.sin(2 * np.pi * 500 * t) + np.sin(2 * np.pi * 4000 * t)
x = torch.tensor(x_np, dtype=torch.float32).view(1, 1, -1)

# Design prototype lowpass filter (32 taps, cutoff at pi/2 -> 4000 Hz for fs=16kHz)
num_taps = 32
h0_coeffs = firwin(num_taps, cutoff=0.5, window='hamming')

# Create complementary highpass filter via frequency shift: h1[n] = (-1)^n * h0[n]
n_idx = np.arange(num_taps)
h1_coeffs = h0_coeffs * ((-1)**n_idx)

# ==========================================
# 2. Polyphase Decomposition of the Bank
# ==========================================
# Split H0 (Lowpass) into even (E00) and odd (E01) polyphase branches
e00 = h0_coeffs[0::2]
e01 = h0_coeffs[1::2]

# Split H1 (Highpass) into even (E10) and odd (E11) polyphase branches
e10 = h1_coeffs[0::2]
e11 = h1_coeffs[1::2]

# Construct the 2x2 Polyphase Matrix Filter Weights
# Shape: (out_channels=2, in_channels=2, kernel_size=16)
# Row 0 computes the Lowpass subband; Row 1 computes the Highpass subband.
w_bank = torch.tensor([
    [e00, e01],  # Lowpass branch filters for [even_input, odd_input]
    [e10, e11]   # Highpass branch filters for [even_input, odd_input]
], dtype=torch.float32)

# ==========================================
# 3. Executing the Analysis Bank
# ==========================================
# Step A: Decompose input into 2 phases (even samples and odd samples)
# Shape becomes (batch=1, channels=2, length=4000)
x_poly = x.view(1, -1, 2).transpose(1, 2)

# Step B: Apply the 2x2 polyphase matrix convolution at the lower rate
# out_channels=2 yields [Lowpass_subband, Highpass_subband] simultaneously
subbands = F.conv1d(x_poly, w_bank, stride=1)

# Separate the outputs
y_low = subbands[:, 0:1, :]   # Low-frequency content (500 Hz preserved)
y_high = subbands[:, 1:2, :]  # High-frequency content (4000 Hz preserved)

# ==========================================
# 4. Verification
# ==========================================
print(f"Original signal shape:     {x.shape}")
print(f"Lowpass subband shape:     {y_low.shape}  (Sampling rate halved to 8 kHz)")
print(f"Highpass subband shape:    {y_high.shape} (Sampling rate halved to 8 kHz)")

# Verify frequency separation using simple energy check
print(f"Lowpass subband energy:    {torch.sum(y_low**2).item():.2f}")
print(f"Highpass subband energy:   {torch.sum(y_high**2).item():.2f}")

```

### Why This Matters for Week 7 and ML Architectures

In modern deep learning, this exact multi-rate polyphase structure maps onto **Wavelet Scattering Transforms** and specialized **subband neural network front-ends** (such as those used in raw audio models like WaveNet or speech recognition front-ends).

By structuring the downsampling and frequency separation as a parallel matrix operation (`groups=1` or full matrix multiplication over polyphase channels), you eliminate redundant calculations on discarded samples. This allows edge devices to process high-frequency sensor or audio streams at a fraction of the computational cost while maintaining strict control over aliasing boundaries.
